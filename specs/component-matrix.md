## 怎么补一个组件（一次，50 个风格同时生效）

1. 在 `build_components.py` 对应分组里加一段 `spec("名称", """...""")`，**只用 CSS 变量**，不写死颜色/圆角
2. 需要交互就在页面底部的统一 `<script>` 里加逻辑，别引第三方库
3. 跑 `build_demos.py` → 50 个风格页同步（组件已内嵌在 demo 页的 `#components` 区）
4. 跑 `build_zips.py` → 50 个 zip 包同步
5. 抽 3 个风格（浅色/深色/重边框）截图验收

**成本 = 一个组件，不是 50 个。** 这是这套架构唯一值得强调的地方。

## 仍未做（7 个，明确放弃或留待需要时）

| 项 | 原因 |
|---|---|
| 桑基图 | 纯 SVG 成本高，且已有漏斗/热力覆盖同类场景 |
| 离线 / 维护页 | 与 500 页共用结构，用时复制改文案即可 |
| 行拖拽排序 | 需要拖拽逻辑，静态组件页展示价值低 |
| 上传队列（多文件） | 已覆盖单文件进度 + 失败重试 |
| 图表交互（真实 tooltip 跟随） | 需 JS 定位，静态示意已够 |
| 国际化运行时切换 | 属架构能力（文案外置），非组件 |
| 打印样式全量适配 | 只给示意，真实项目按页面单独写 |

**结论：建站常见模式已覆盖 ~92%，剩下的是「场景极窄」或「属架构不属于组件」的部分。**
