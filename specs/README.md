# 怎么让 AI 照着某个风格做设计

三种喂法，产出质量差一个档。先看结论，再看具体做法。

| 喂法 | 你提供 | AI 能产出 | 适用 |
|---|---|---|---|
| **A. 名称 + 1 张图** | 「新粗野主义」+ 一张截图 | 一屏像样的**皮肤**，第二屏开始飘，组件退回默认长相 | 快速试色、找感觉 |
| **B. 风格规格卡**（推荐） | 一份 spec（tokens + 组件配方 + 反模式） | **多页一致**的可交付页面，允许改文案改结构 | 真做项目 |
| **C. 规格卡 + 一个样例页** | spec + 本仓库该风格的 demo HTML | 最稳，风格还原度最高 | 团队复用、换 AI 也要一致 |

---

## A. 只给名称和图（最快，60 分）

能拿到的：主色、明暗、字体气质、圆角、密度。
拿不到的：栅格、间距尺度、hover/focus/disabled、表格/弹窗/空态长什么样、无障碍兜底。

**如果只能用图，至少做这三件事**，能把 60 分拉到 75：

1. **给 3 张图，不是 1 张**——一张图是「一个巧合」，三张图才能反推出「不变的规则」。
2. **明说要哪些组件的状态**：「按钮的 hover / disabled / focus 三态都要，表格要 10 行，要一个弹窗和一个空状态」。图里没有的，你不说它就给你默认 Bootstrap。
3. **给负面约束**。负面约束比正面描述有效得多：
   ```
   禁止：圆角、模糊阴影、渐变、半透明、衬线字体、>200ms 的过渡动画
   ```

---

## B. 给规格卡（推荐，80 分）

规格卡 = 把「感觉」翻译成「可执行参数」。每种风格一份，见 `specs/*.md` 与 `specs/*.json`。

一个完整的规格卡包含 7 块：

1. **Tokens**：背景/表面/文字/次要文字/描边/主色/主色上的文字、圆角、间距、阴影、字体
2. **移动语汇**：3–5 个必须出现的手法（硬阴影偏移、点阵底纹、等宽大写标签…）
3. **组件配方**：按钮 / 输入 / 卡片 / 表格 / 徽章 / 弹窗 / Toast / 空态 / 加载态
4. **反模式**：这风格绝不能出现什么（比"要什么"更容易执行）
5. **无障碍兜底**：对比度下限、focus 可见性、触摸目标
6. **影像处理**：照片用什么滤镜（去饱和 / 双色调 / 噪点 / 明度压缩）
7. **参考站点**：2–3 个，用于 AI 校准，而不是让它自由发挥

### 可直接复制的提示词

```
你是资深前端工程师兼视觉设计师。

【风格】新粗野主义 Neo-Brutalism
【规格】<把 specs/01-neo-brutalism.md 全文粘进来>

【任务】为「一个 SaaS 数据看板」设计并实现 {页面类型}，输出单文件 HTML + CSS + 少量 JS。

【硬约束】
1. 只能使用规格里的 tokens，不得引入任何新颜色；需要深浅变化时用 color-mix 派生。
2. 每个组件必须实现规格里写的三态（default / hover / focus-visible），disabled 也要有。
3. 严格遵守「反模式」清单，一条都不能破。
4. 页面结构：导航（sticky）→ Hero → 组件区 → 数据表格 → 空态/错误态 → 页脚。
5. 图片用 <img> + 规格里的滤镜参数；不要用渐变色块冒充图片。
6. 代码里给每个 token 加一行注释，说明它控制什么。

【自检】输出前逐条核对「验收清单」，把不满足的项标出来并修正。
```

## C. 加一个样例页（90 分）

最有效的 few-shot 不是形容词，是**结构**。把本仓库对应 demo 的 HTML 直接贴进去，加一句：

```
参考这个页面的「结构」和「类名组织方式」，
但把它的风格 tokens 全部替换成下面这份规格里的值。
不要改动 DOM 结构，只改 CSS 变量和规则。
```

这样 AI 不用猜「组件区该有哪些东西」，只在它最擅长的「样式替换」上出力。

## 让输出更稳的 7 个技巧

1. **先让它输出 token 表，再让它写代码。** 两步走，比一步到位稳得多——先对齐参数，避免它写着写着自创颜色。
2. **一次只做一个区块。** "先做导航和 Hero，我确认后再做组件区"。整页一次生成，五屏之后必然崩。
3. **给负面清单。** 模型对"不要什么"的执行力，明显强于对"要什么"。
4. **要求它声明取舍。** "如果某个组件在规格里没定义，先告诉我你打算怎么做，不要自己发明。"
5. **用截图回环。** 生成后截图，让它自己对照「验收清单」找问题，比人肉挑错快。
6. **锁定字体来源。** 中文环境写明 `PingFang SC / Noto Sans SC`，不然它会给你 `Inter` + 一堆豆腐块。
7. **别让它选风格。** 让它执行风格。选风格交给人或 `previews.html`。

## 验收清单（生成后逐条过）

**视觉**
- [ ] 主色只出现在该出现的地方，没有第三种颜色偷偷混进来
- [ ] 圆角、阴影、描边与 tokens 完全一致（用 DevTools 抽查 3 个元素）
- [ ] 字号/行高/字距符合规格，长文本不溢出
- [ ] 图片滤镜生效，跟页面色调不打架

**交互**
- [ ] hover / focus-visible / disabled / active 四态都有，且明显不同
- [ ] 表格 10 行以上不塌、不横向溢出
- [ ] 空态、错误态、加载态都有，不是"暂无数据"四个字
- [ ] 弹窗能 Esc 关闭、点遮罩关闭

**无障碍**
- [ ] 正文对比度 ≥ 4.5:1，大字 ≥ 3:1
- [ ] focus 环可见（不是 `outline:none`）
- [ ] 触摸目标 ≥ 44×44px
- [ ] 信息不只靠颜色传达（状态除了颜色还有文字/图标）

## 本仓库怎么配合用

- `specs/NN-风格名.md` —— 人读 + 直接粘给 AI
- `specs/NN-风格名.json` —— 机器读（可喂给脚本、可做 token 生成器）
- `demos/NN-风格名.html` —— 样例页，做 few-shot 用
- `assets/thumbs/NN.jpg` —— 一张图，做快速风格锚定用

三种东西一起给，是目前最稳的组合：**规格定规则，样例定结构，图定感觉。**
